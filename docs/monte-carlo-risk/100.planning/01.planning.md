## 1. Domain Discovery & Business Translation

### Ubiquitous Language (frozen glossary)

These terms are the single source of truth for code, tests, docs, and conversation. Any new term requires an ADR to add.

| Term            | Definition                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Portfolio**   | The user's declared set of holdings, identified by ticker, with weights summing to 1.0.                                    |
| **Holding**     | A single ticker + weight pair inside a Portfolio. Value object.                                                            |
| **Ticker**      | A vendor-neutral symbolic identifier of a security. Today a free-form string; future versions will resolve to FIGI/PermID. |
| **Weight**      | The fraction of capital allocated to a Holding. A non-negative Decimal in `[0, 1]`.                                        |
| **Return**      | A daily log return. Scalar `float`.                                                                                        |
| **Path**        | One simulated trajectory of cumulative portfolio value across the horizon. `numpy.ndarray` of shape `(horizon + 1,)`.      |
| **Drawdown**    | Peak-to-trough decline along a single Path. Scalar or time series.                                                         |
| **VaR (α)**     | Value-at-Risk at confidence `α` over the horizon. The `α`-quantile of the terminal-wealth loss distribution.               |
| **CVaR (α)**    | Expected Shortfall — the mean loss conditional on loss exceeding VaR(α).                                                   |
| **Mock return** | A synthetic daily log return sampled from a calibrated distribution; not real market data.                                 |
| **Run**         | One end-to-end CLI invocation with frozen inputs and a deterministic RNG seed.                                             |

### Event Storming (past-tense events)

| #   | Event                   | Trigger                                              | Actor                      | Source context | Downstream consumers        |
| --- | ----------------------- | ---------------------------------------------------- | -------------------------- | -------------- | --------------------------- |
| 1   | `PortfolioDefined`      | CLI parses `--portfolio` flag or config file         | User (via CLI)             | Portfolio      | Application orchestrator    |
| 2   | `MarketDataLoaded`      | `MarketDataSource.load()` returns a `ReturnMatrix`   | `MarketDataSource` adapter | Infrastructure | Application orchestrator    |
| 3   | `SimulationStarted`     | Application orchestrator invokes `Simulation.run()`  | Application                | Application    | Simulation                  |
| 4   | `SimulationCompleted`   | `Simulation.run()` returns a `PathSet`               | Simulation                 | Simulation     | Application → RiskMetrics   |
| 5   | `RiskMetricsCalculated` | `RiskMetrics.compute()` returns a `RiskReport`       | RiskMetrics                | RiskMetrics    | Application → Visualization |
| 6   | `ChartsRendered`        | `Visualization.render()` writes PNG + JSON artifacts | Visualization              | Visualization  | User (filesystem)           |

All events are **in-process, synchronous, value-object payloads** — there is no message broker, no Kafka, no SNS/SQS in v1. AsyncAPI is therefore not produced; JSON Schemas for each event are stored at `contracts/events.schema.json` as a frozen in-process contract (see §4 Anti-patterns note).

### Bounded Contexts

Locked from `00.defining.md` §2 Bounded Contexts. Vocabulary below is the one used in code.

| Context           | Aggregate Root  | Vocabulary (this context only)                                           | Owns Events                                |
| ----------------- | --------------- | ------------------------------------------------------------------------ | ------------------------------------------ |
| **Portfolio**     | `Portfolio`     | `Portfolio`, `Holding`, `Ticker`, `Weight`                               | `PortfolioDefined`                         |
| **Simulation**    | `SimulationRun` | `SimulationRun`, `PathSet`, `Path`, `RNGSeed`, `Horizon`, `n_paths`      | `SimulationStarted`, `SimulationCompleted` |
| **RiskMetrics**   | `RiskReport`    | `RiskReport`, `VaR`, `CVaR`, `MaxDrawdown`, `TerminalWealthDistribution` | `RiskMetricsCalculated`                    |
| **Visualization** | `ChartArtifact` | `ChartArtifact`, `Histogram`, `FanChart`, `DrawdownChart`                | `ChartsRendered`                           |

**Context seams.** All inter-context communication is one-way through the application layer:
`Portfolio → Simulation → RiskMetrics → Visualization`. Contexts share only the value objects in the shared kernel (`Ticker`, `Weight`, `Return`, `Currency`, `RunId`). No context imports another context's aggregates.

## 2. Non-Functional Requirements (NFRs) & Constraints

### Quantified NFRs

All NFRs below are asserted by automated checks (CI benchmark or unit test). "Fast" without a number is rejected.

| ID    | NFR                            | Target                                                                                                                              | How measured                                            | Source                                   |
| ----- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------- |
| NFR-1 | Default run wall-clock latency | **P50 ≤ 10 s, P95 ≤ 30 s** on a modern laptop (10k paths × 252 days × ~30 assets)                                                   | `pytest-benchmark` in CI; fails build if exceeded       | Defining §1 Targets & Budget             |
| NFR-2 | Test suite execution time      | **Full unit suite ≤ 5 s**; **integration suite ≤ 30 s**; **E2E suite ≤ 20 min**                                                     | `pytest --durations` in CI; warning at 80% of budget    | Defining §4 Modern Test Pyramid          |
| NFR-3 | Domain purity                  | **Zero forbidden imports** in `domain/` (no `pathlib`, `requests`, `typer`, `click`, `matplotlib`, no infrastructure-layer imports) | `import-linter` job in CI; fails build                  | Defining §3 Layer Enforcement            |
| NFR-4 | Reproducibility                | **Same `(seed, portfolio, n_paths, horizon, mock_data_version)` → bit-identical outputs**                                           | Deterministic unit test on RNG seeding                  | Defining §3 Observability                |
| NFR-5 | Idempotent CLI                 | **Repeated runs with identical inputs produce byte-identical PNG + JSON artifacts**                                                 | Integration test on `output/` after two runs            | Defining §3 Story Slicing (unhappy path) |
| NFR-6 | Error contract                 | **Every CLI failure emits one canonical JSON error line to stderr** with `error_code`, `message`, `context`, `run_id`               | Snapshot test on captured stderr                        | Defining §3 Observability                |
| NFR-7 | One-command bootstrap          | **Clean machine → green CI in ≤ 5 min**                                                                                             | Manual + CI verification; `make bootstrap && make test` | Defining §3 Sprint Zero                  |
| NFR-8 | Cost ceiling                   | **$0/month cloud spend**                                                                                                            | Self-enforcing (no cloud infra exists)                  | Defining §1 Targets & Budget             |

### CAP stance per context

All four contexts are **AP (best-effort, partition-tolerant)** by default. There is no replication, no consensus, and no network partition in v1; consistency collapses to "single-process in-memory state" and needs no further negotiation. Documented in **ADR-001** §Consequences.

### Cloud budget

**$0/month** — the project runs locally in Docker. No serverless, no always-on nodes, no managed databases. If v2 introduces a hosted market-data cache, the budget must be re-negotiated before the ADR is written.

### SLA / SLO

**No external SLA.** The internal SLO is NFR-1 (default run wall-clock). Error budget: if P95 exceeds 30 s for 3 consecutive CI runs, treat as a regression and open a spike. No customer-facing SLO exists because there are no customers.

| ------- | ----------------------------------------------------------------------------- | ---------- |
| ADR-001 | Strict hexagonal architecture with `import-linter` enforcement                | ✅ Accepted |

### Anti-patterns explicitly rejected

| Anti-pattern                      | Why rejected here                                                                                                                                                                                                                  | Source rule                     |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| **Anemic Domain Modeling**        | Rejected. Aggregates (`Portfolio`, `SimulationRun`, `RiskReport`, `ChartArtifact`) own their behavior; no CRUD-only repositories.                                                                                                  | Playbook §Avoid                 |
| **Gold-Plating Scalability**      | Rejected. No sharding, no multi-region, no horizontal scaling. Single-process CLI by design; cloud budget is $0.                                                                                                                   | Playbook §Avoid                 |
| **Resume-Driven Development**     | Rejected. No Kafka, no Kubernetes, no event bus in v1. Boring Python stdlib + numpy + matplotlib. If a real broker is needed, an ADR must justify it.                                                                              | Playbook §Avoid                 |
| **Living Document Specification** | Rejected. Contracts in `contracts/` are frozen. Any change requires a new contract version, a new ADR, and a new ticket.                                                                                                           | Playbook §Avoid                 |
| **Forcing OpenAPI on a CLI tool** | Rejected in spirit. We produce a frozen CLI contract in `contracts/cli-contract.yaml` because OpenAPI request/response semantics don't apply to a CLI. If v2 adds an HTTP service, an OpenAPI spec is produced then and only then. | Playbook §Avoid (resume-driven) |

## 4. Deliverables (Definition of Ready)

### 1. ADRs

Five ADRs in `adr/`. See file list in §3 above.

### 2. API Contracts

- **`contracts/cli-contract.yaml`** — frozen CLI surface (commands, flags, return codes, JSON output schema, stderr error schema). Versioned at `v1.0.0`. Any change → `v1.x.y`.
- **No `openapi.yaml`** in v1. Justified by ADR-005 (CLI-only) and the resume-driven anti-pattern.
- **No `asyncapi.yaml`** in v1. There is no message broker; domain events are in-process value objects whose schemas live at `contracts/events.schema.json` (JSON Schema, versioned).

### 3. Event Schemas

- **`contracts/events.schema.json`** — JSON Schema (draft 2020-12) defining the payload shape of every past-tense event from §1 Event Storming. Versioned at `v1.0.0`. Treated as the in-process contract between contexts.

### 4. C4 Diagrams

- **`diagrams/c4-context.md`** — System context: user, the CLI tool, the bundled mock CSV corpus, and the future market-data API.
- **`diagrams/c4-container.md`** — Container view: the four bounded contexts (`Portfolio`, `Simulation`, `RiskMetrics`, `Visualization`) as application-layer components inside a single Python process, plus the `MarketDataSource` infrastructure port.

### 5. State Machines

- **`diagrams/state-machine-simulation-run.md`** — for `SimulationRun`: legal transitions `Pending → Running → Completed` and `Pending → Running → Failed`; explicitly forbidden `Running → Pending`, `Completed → Running`, `Failed → Running` (one-shot semantics).
- `Portfolio`, `RiskReport`, and `ChartArtifact` are value-object-shaped and have no lifecycle of their own; no state machines required.

## Quick-Reference Summary

### Mission
Convert the frozen `00.defining.md` into the immutable technical contracts (ADRs, CLI contract, event schemas, C4 diagrams, state machine) that the 200 / 300 / 400 phases will build against in parallel — without re-asking product. Lock the bounded-context vocabulary, quantified NFRs, and hexagonal architecture so downstream phases can split work without coordination overhead.

### Key Decisions
- **ADR-001** — Strict hexagonal + `import-linter` enforces domain purity; CI fails build on violation.
- **ADR-002** — `numpy` is a domain primitive (not infrastructure); matplotlib and HTTP libs are forbidden in domain.
- **ADR-003** — `MarketDataSource` is a Python `Protocol`; mock v1, real HTTP adapter is v2 work gated by Spike S-001.
- **ADR-004** — No persistence in v1; runs are reproducible from `(seed, portfolio, n_paths, horizon)` alone.
- **ADR-005** — CLI-only v1; no HTTP service surface, no message broker.
- **Anti-patterns rejected:** anemic modeling, gold-plating, resume-driven tech, living specs, forced-OpenAPI-on-CLI.
