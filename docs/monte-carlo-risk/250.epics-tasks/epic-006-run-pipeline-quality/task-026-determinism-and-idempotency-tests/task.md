## Context

The tests that prove NFR-4 and NFR-5. Run the full pipeline twice with identical inputs and assert byte-identical artifacts. Traces to Stories 6.2.

## Acceptance Criteria (BDD)

- [ ] **Scenario 1 (Happy Path — Idempotency):** Given two consecutive `simulate` runs with identical `--seed` and other inputs, `When` I `diff -r` their output directories, `Then` `simulation_report.json` and all 3 PNGs are byte-identical. (The `run_id` field in the JSON is generated deterministically from the seed for idempotency tests, OR is excluded from comparison — choice documented in the test).
- [ ] **Scenario 2 (Sad Path — Provider Not Implemented):** Given `--provider http`, `When` I run the idempotency test, Then the test suite skips the idempotency assertion for the HTTP provider (it's v2) and records an `xfail` marker. The Mock provider's idempotency is fully tested.
- [ ] **Edge Case (Mandatory):** If a developer accidentally introduces non-determinism (e.g., adds `time.time()` to the simulation, or uses `np.random.rand()` without seeding), this test MUST fail with a clear message pointing at the per-file SHA-256 mismatch. The test provides the exact diff (which file, which byte range) so the developer can find the bug quickly.
