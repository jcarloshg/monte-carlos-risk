## Context

The end-to-end "clean clone → green pipeline" gate. The CI job builds the Docker image from scratch, runs the full `simulate` command inside, and compares output against a golden file. Traces to Story 6.4. The capstone deliverable of the initiative.

## Acceptance Criteria (BDD)

- [ ] **Scenario 1 (Happy Path):** Given a clean git clone on a Linux CI runner, `When` `make docker-smoke` runs (which: builds the image, runs the full `simulate`, compares against golden), `Then` exit code is 0 and the output diff against `tests/fixtures/golden/` is empty.
- [ ] **Scenario 2 (Sad Path):** Given a developer changes the matplotlib `rcParams` (e.g., changes DPI from 100 to 150), `When` the E2E smoke runs, `Then` it fails with a clear "PNG hash mismatch" message and a side-by-side of expected vs actual. The developer MUST regenerate the golden (explicit, two-step process) rather than the test silently updating it.
- [ ] **Edge Case (Mandatory):** If the Docker image build itself fails (e.g., `pip install` error from PyPI), the smoke test MUST fail before the simulation step (no false-positive green). The CI job fails fast with the build log surfaced.

## Deliverables

- `tests/fixtures/golden/` — committed golden artifacts (1× `simulation_report.json` + 3× PNGs) generated by running `task-026`'s determinism test and reviewed in a separate commit.
- `scripts/regenerate_golden.sh` — explicit, two-step process for regenerating goldens (requires a manual "yes I want to overwrite the golden" prompt; not CI-automated).
- Extension to `.github/workflows/ci.yml` — the `docker-smoke` job (already exists from `task-004`'s placeholder) is upgraded to: `make docker-build && make docker-smoke`.
- Extension to `Makefile` — `docker-smoke` target builds the image, runs the simulate inside it, diffs output against the golden.
- `tests/e2e/test_docker_smoke.py` — Python pytest that invokes `make docker-smoke` as a subprocess, captures exit code, asserts the diff against the golden is empty. Skipped locally; CI-only via marker.
- `CONTRIBUTING.md` (extend) — adds a "When the E2E smoke fails" section explaining the diff workflow + regenerate-golden procedure.
